Realtime Connections · chapter deep dive

Choose the connection shape that matches the conversation.

Long polling, Server-Sent Events, and WebSockets all deliver timely updates, but they create different connection lifecycles, traffic directions, infrastructure demands, and failure modes.

HTTP

Long polling

Client
GET /events?cursor=42 →request waits
API instances
← event or timeoutthen reconnect
Event store / broker
  1. Client sends a normal HTTP request with its last cursor.
  2. Server holds the request until an event arrives or a timeout expires.
  3. Server returns one response; the client processes it and immediately opens another request.

Best fit: broad HTTP compatibility and infrequent updates when true streaming infrastructure is unavailable.

Watch connection counts, timeout alignment, reconnect gaps, duplicate delivery, and load-balancer idle limits.

Server-Sent Events

EventSource
← text/event-streamid · event · data
Proxy / gateway
← subscribed eventsheartbeat keeps stream open
Service + pub/sub
  1. Browser opens one HTTP GET and the server keeps the response stream open.
  2. Server emits UTF-8 events with IDs; intermediaries must not buffer the stream.
  3. EventSource reconnects automatically and can send Last-Event-ID to resume.

Best fit: notifications, dashboards, progress, and feeds where traffic is predominantly server → client.

Plan heartbeat cadence, replay retention, per-origin connection limits, proxy buffering, and slow-client backpressure.

WebSockets

WebSocket client
⇄ framesafter HTTP Upgrade
WebSocket gateway
⇄ route / fan-outconnection ID + topic
Services + pub/sub
  1. Client performs an authenticated HTTP Upgrade handshake.
  2. One persistent connection carries independent messages in both directions.
  3. At scale, gateways register connections and use shared pub/sub so any service can reach the owning gateway.

Best fit: chat, multiplayer, collaborative editing, trading, and interactive bidirectional protocols.

Handle authentication renewal, ping/pong, ordering, bounded send queues, backpressure, reconnect/resume, and rolling gateway drains.

Interview shortcut: start with the least stateful option. Use long polling for compatibility, SSE for one-way streams, and WebSockets only when the client and server both need low-latency independent messages. Open the Realtime Connections chapter.
