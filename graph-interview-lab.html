01 · Core language

Know the graph before choosing the algorithm.

Click any card to expand it. These adjectives determine which algorithms are valid.

+

Directed vs. undirected

Does an edge have an arrow?

Directed: follows one-way relationships, like course prerequisites. Undirected: symmetric, like friendship. In-degree counts incoming arrows; out-degree counts outgoing arrows.
+

Weighted vs. unweighted

Does each edge have a cost?

Use BFS for shortest edge count in unweighted graphs. Use Dijkstra for non-negative weights and Bellman–Ford when negative edges are possible.
+

Cyclic vs. acyclic

Can you return to where you started?

A DAG is a directed acyclic graph. DAGs support topological ordering and dynamic programming over dependencies.
+

Connected components

How many separate “islands” exist?

In undirected graphs, repeatedly BFS/DFS from an unvisited node. In directed graphs, “strongly connected” means every node can reach every other node in the component.
+

Tree vs. graph

A tree is a constrained graph.

A connected undirected graph with no cycles is a tree: exactly V − 1 edges and one simple path between every pair. Rooting it adds parent/child semantics.
+

Density

How close is E to V²?

Sparse graph: E ≈ V, favor adjacency lists. Dense graph: E ≈ V², a matrix may be appropriate. Complete undirected graph has V(V−1)/2 edges.
Input relationships→directed?→weighted?→cycles?→choose algorithm
02 · Representation

The data structure changes the runtime.

Adjacency list

Store each vertex’s neighbors. Best default for sparse graphs.

A → [B, C]
B → [A, D, E]
C → [A, F]
D → [B]
E → [B, F]
F → [C, E]

Adjacency matrix

A V×V boolean/weight table. Fast edge lookup, expensive space.

    A B C D E F
A [ 0 1 1 0 0 0 ]
B [ 1 0 0 1 1 0 ]
C [ 1 0 0 0 0 1 ]
D [ 0 1 0 0 0 0 ]
E [ 0 1 0 0 0 1 ]
F [ 0 0 1 0 1 0 ]

Edge list

Just the edges. Ideal when algorithms sort/process edges directly.

[(A,B), (A,C), (B,D),
 (B,E), (C,F), (E,F)]

07 · Interview patterns

Most graph questions wear a disguise.

1

Grid → implicit graph

Each cell is a vertex; legal moves are edges. Use direction vectors, bounds checks, and visited marking. Examples: islands, shortest path in maze, rotting oranges.

2

Words → state graph

A state is a vertex; one valid transformation is an edge. BFS finds minimum transformations. Example: Word Ladder.

3

Prerequisites → DAG

“Must happen before” creates directed edges. Topological sort returns an order; processing fewer than V nodes proves a cycle.

4

Accounts / groups → components

Shared identifiers connect records. DFS/BFS works; Union-Find shines when edges stream in or connectivity is repeatedly queried.

5

Cheapest route → weighted path

Identify weight constraints first. Non-negative → Dijkstra. Negative → Bellman–Ford. DAG → topological DP can be faster.

6

Copy / serialize → traversal + map

Map original node → cloned node before traversing neighbors. The map both prevents cycles and preserves shared references.

Say this out loud in an interview

“I’ll model each ___ as a vertex and each ___ as an edge. The graph is [directed/undirected] and [weighted/unweighted]. I need [reachability/shortest path/order/connectivity], so I’ll use ___. I’ll track visited when I enqueue/push to avoid duplicates. Runtime is O(V+E), and space is O(V).”

Cycle detection

Undirected: DFS with parent, or Union-Find.

Directed: DFS with 3 colors / recursion-stack set, or Kahn processes fewer than V.

Common traps

Mark visited on enqueue/push, not removal. Handle disconnected graphs. Don’t use Dijkstra with negative edges. Distinguish MST from shortest-path tree. Clarify parallel edges and self-loops.
